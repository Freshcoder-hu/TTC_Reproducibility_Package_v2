# Data notes — `formal.jsonl` and its standardised copy

## The problem

`02_Perception_Robustness/results/formal.jsonl` is the author's raw dump of the
2,340 formal robustness cells. It is **not strict JSON**: the file contains the
bare tokens

```
NaN        Infinity        -Infinity
```

which RFC 8259 does not define. Python's `json` module accepts them by default,
so the original analysis pipeline worked; `jq`, JavaScript, Go, Rust, most
parquet/CSV loaders and strict validators do not.

There are **32 distinct fields** that can be non-finite. The most frequent:

| field | kind | rows (of 2340) | meaning |
|---|---|---|---|
| `first_contact_time_rr` | `Infinity` | 2315 | robot–robot contact never happened |
| `first_contact_time_rs` | `Infinity` | 1693 | robot–animal contact never happened |
| `recovery` | `NaN` | 1570 | run had no recovery phase |
| `dur_recover`, `recover_start_1`, `recovery_success_rate` | `NaN` | 1570 | same reason |
| `t_pre_on`, `ttc_lead`, `dur_pre` | `NaN` | 1568 | pre-emption never triggered |

Note that `Infinity` here is **meaningful**: "this contact never occurred".
Replacing it with `0` would claim an instantaneous contact at t = 0, and
replacing `NaN` with `0` would invent a recovery duration of zero. Either
substitution silently corrupts every downstream mean.

## The standardised copy

`02_Perception_Robustness/results/formal_standardised.csv`
(4.22 MiB, 2,340 rows, 226 columns) is generated by

```
python tools/standardise_formal.py --verify
```

with these rules:

* a non-finite value becomes an **empty cell**, never `0` and never a number;
* a genuine JSON `null` (field absent for that run) is also an empty cell, but
  it is **not** listed as non-finite, so "missing" and "non-finite" stay
  distinguishable;
* the trailing column **`_nonfinite`** names exactly which cells were
  non-finite and of which kind, e.g.

  ```
  recovery=NaN;role_switches=NaN;t_pre_on=NaN;ttc_lead=NaN;
  first_contact_time_rr=Infinity;sp_r_req_mean=NaN;...
  ```

* every finite number is written with `repr()` so it round-trips to the same
  float.

`--verify` re-reads the CSV, reconstructs each record and compares it cell by
cell with the original line; it fails if any non-finite value leaked out as a
number, if a marker does not match the original value, or if any finite value
changed. Measured result: **every one of the 2,340 rows round-trips**, 2,340 of
2,340 rows carry at least one non-finite value, and they are all accounted for
by the marker column.

Use the original `.jsonl` when you need byte-for-byte provenance; use the
`.csv` when you need a loader that refuses non-standard tokens. They carry the
same information.

## Reading the original safely

```python
import json, math

with open("02_Perception_Robustness/results/formal.jsonl", encoding="utf-8") as fh:
    rows = [json.loads(line) for line in fh if line.strip()]

# keep "never happened" apart from "zero"
contact = [r["first_contact_time_rr"] for r in rows]
never   = sum(1 for v in contact if v == math.inf)
```

Do **not** call `json.dumps(rows)` — it will happily emit the non-standard
tokens back out, and a strict consumer downstream will reject the file.

| `formal.manifest.json` | per-run hashes and configuration for the above |

| `formal_attempt1.jsonl` | earlier partial attempt; audit only |
| `pilot_v1.jsonl`, `regression_blackout.jsonl` | pilots and a blackout regression probe; never part of the formal denominator |

Only `formal.jsonl` (or its standardised CSV) may be used for the formal
numbers. The checkpoint and attempt files must not be concatenated with it.
